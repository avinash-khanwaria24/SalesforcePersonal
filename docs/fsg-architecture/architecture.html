FreshSource Global · Salesforce Architect design

Enterprise architecture visual pack

Core + Experience Cloud LWR + B2B Commerce + Order Management. Designed for 50k orders/day, 150k branch buyers, 8k suppliers, 14 time zones, and LDV constraints. Full narrative lives in FSG_ENTERPRISE_SOLUTION_ARCHITECTURE.md.

Capability map

1. Supplier network

Public LWR apply → Q&C territory queue → Partner users, localized catalog, pickup schedules.

2. Corporate B2B

HQ Contract → Cluster Accounts → Branch Buyer Accounts. Chefs register by corporate email + store code. One branch manager administers only that branch.

3. Micro-buyers

Self-register on regional store. Dynamic buyer group from country/region. Wholesale cart + invoices.

4. Pricing

Multi-currency PBE + volume tiers + pricing extension (weight × temperature × urgency × contract).

5. Fulfillment tiers

Standard Ground, Express Cold-Chain, Priority Ultra-Fresh as Order Delivery Methods, allocated from DC Locations.

6. LDV controls

No 15k-child HQ, no 150k CC+ roles, category entitlements, order archive, telemetry off-core.

Sharing in one picture

Internal

OWD Private. Enterprise Territory Management shares Accounts by geography. Role hierarchy is organizational, not a clone of the map. Inspection and pickup records master-detail to Account so they inherit.

External store

High Volume Community + Sharing Sets: User.AccountId = store Account. Branch manager is CC+ Super User + delegated admin on that Account only. Products are not shared; they are entitled.

Answers to the eleven design questions

#QuestionDecision
1Multi-currency?Yes, plus Advanced Currency Management. Transaction currency on Account/Cart/PBE/OrderSummary; dated rates for history and rebates.
2Enterprise Territory Management?Yes for internal coverage and inspections. No for catalog or branch isolation.
3Objects?Standard Account/Contract/Buyer/Product/WebStore/OrderSummary/Location plus custom application, certification, inspection, pickup, rebate, store profile.
4Account assigned to region?Indexed Region_Code__c + ETM rules; clusters under HQ; buyers isolated by Account not territory.
5License fees?See table above and the architecture document section 10.
6Data model?HQ → Cluster → Branch Buyer; three regional WebStores; category entitlements; managed OM.
7Sharing?Private OWD, ETM internal, Sharing Sets HV, Super User/CC+ per branch, entitlements for products.
8Profiles / roles / permission sets?One profile per license family; PSGs by persona; HV chefs; CC+ managers only.
9Regional products and currency?Buyer Group + WebStore + category entitlement; PBE in Account currency.
10Store-related records?All transactions on Branch Account; Sharing Set + Super User; effectiveAccountId.
11Product setup?One global SKU; region via catalog/inventory; pack as variations; three delivery methods; pricing extension for weight/temp/urgency/contract.
