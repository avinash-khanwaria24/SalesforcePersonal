# 2.1 Spoilage & Dynamic Pricing Engine (SDPE)

## Salesforce Architecture Design — FreshSource Global (FSG)

**Best-path design** (Sales Cloud + Service Cloud + Experience Cloud; SDPE remains an **external** engine).  
**Depends on:** 1.4 `FsgPricingService` (Price Books + fulfillment rate cards), 1.5 RDC inventory, 1.2/1.3 authenticated checkout.  
**Contrast:** 2.2 GFSR is **fail-closed** at dispatch. SDPE is **fail-open** at checkout so the cart always completes.

**Salesforce patterns used:** *Remote Process Invocation — Request and Reply*; Named / External Credentials; Platform Cache (optional hot layer) + durable custom object; Queueable for cache warm/retry; **no** browser callouts; **no** Salesforce Connect for a pricing *engine*.

---

## 1. Designed problem statement

At checkout, Salesforce must:

1. Build **inventory context** (SKU, qty, RDC, temperature class, available qty, ship date).
2. Call FSG’s **SDPE** for perishable **dynamic prices** (remaining shelf-life, demand, discounts).
3. Apply those unit prices to goods lines, then add **1.4 fulfillment** fees.
4. If SDPE is **down, slow, or wrong**, **still check out** using a controlled fallback.
5. Never expose SDPE URLs/keys or another customer’s prices on Experience Cloud.

---

## 2. Best-path decisions (locked)

| Decision | Choice | Why |
| --- | --- | --- |
| Primary get-price | **One batched Apex HTTPS POST** from `FsgPricingService` via Named Credential | Checkout needs the price **now**. Salesforce request–reply pattern. One callout per cart (not per SKU) to stay inside governor limits at 50k orders/day. |
| Timeout | **2–3 seconds** (`HttpRequest.setTimeout`) | UX; then fallback. Do not wait the 120s Apex maximum. |
| Secrets | **Named Credential + External Credential** (named principal) | No secrets in Apex or LWC. Rotate in Setup. |
| Client | **LWC → Apex only** | Browser → SDPE is a security and sharing bypass. |
| Fallback order | **Circuit open? skip callout** → **durable cache** (TTL) → **1.4 Price Book** | Checkout never blocks. Cache is fresher than list; list always exists. |
| Circuit breaker | Custom object/CMDT: N failures → skip SDPE for T minutes | Stops hammering a dead engine and burning callouts. |
| Cache | `SDPE_Price_Cache__c` (External Id = DC code + SKU + currency) | Survives cache eviction; Platform Cache optional in front. |
| Warm cache | Scheduled Queueable + optional **SDPE push** to the same object | After an outage, checkout is already on cache/list. |
| Fulfillment | **Still 1.4 rate cards** | SDPE prices **goods**, not trucks (unless FSG later extends the contract). |
| Floor | CMDT minimum margin vs list | SDPE cannot price below FSG floor. |
| Submit | **Recalculate** the same function; stamp `Price_Source__c` | Buyer cannot post a unit price. |
| Middleware | **Optional MuleSoft** in front of SDPE | Same Apex contract; use if protocol is not REST or ops want the breaker off-platform. |

**Rejected for this problem:** Salesforce Connect (engine ≠ table); Platform Events at Pay-click (too slow); `@future` for the quote; fail-closed cart; Commerce/CPQ.

---

## 3. Inventory context (payload)

Built **on the server** from the cart + 1.5 (home RDC `Primary_DC__c` if not yet allocated):

```text
accountExternalRef, rdcCode, currency,
lines[]: sku, qty, temperatureClass, weightKg, availableQty, requestedShipDate
```

**Do not send:** names, emails, tax ids, payment, other orders, rate-card internals, Salesforce session ids.

---

## 4. Salesforce objects

| Item | Role |
| --- | --- |
| `SDPE_Price_Cache__c` | Last good unit price, discount %, shelf-life hours, `Received_At__c` |
| `SDPE_Health__c` (single org row) | `Failure_Count__c`, `Circuit_Open_Until__c` |
| `SDPE_Callout_Log__c` | HTTP code, latency, correlation id — **no** body PII; purge 7 days |
| `Named Credential` `NC_SDPE` | Outbound URL + auth |
| `Pricebook2` / `PricebookEntry` | Fallback goods (1.4) |
| `Order` / `OrderItem` | Snapshot + `Price_Source__c` = `SDPE` \| `CACHE` \| `LIST` |
| `Case` `SDPE_Outage` | When the circuit opens |

---

## 5. Detailed step-by-step

### A. Setup (once)

1. External Credential (OAuth2 client credentials or API key in headers) + Named Credential `NC_SDPE` (HTTPS only).
2. Custom objects above; **OWD Private** internal and external; **no** Sharing Set to HVU.
3. Permission set `PSG_SDPE_Integration`: CRUD cache/log/health only. Assign to **Integration User** (no role — avoid skew).
4. CMDT `SDPE_Settings__mdt`: timeout ms, retry (0 or 1 on 429/503 only), failure threshold, circuit cool-down, cache TTL, price floor %.
5. Remote Site not required if Named Credential is used (Salesforce recommendation: Named Credential over remote site + hardcoded URL).
6. Experience Cloud: guest **cannot** invoke the pricing class. Buyer profile: Apex class access to `FsgPricingService` only.

### B. Quote (cart — Experience Cloud)

7. Logged-in HVU LWC calls `FsgPricingService.quote(lines)` (`with sharing` **auth first**: Contact.AccountId / ACR).
8. Load 1.5 `RDC_Inventory__c` for `Primary_DC__c` (or allocated DC if present); build payload.
9. Read `SDPE_Health__c` **FOR UPDATE** only when updating the breaker (keep the read short). If `Circuit_Open_Until__c > now`, go to **step 14**.
10. `HttpRequest` to `callout:NC_SDPE/v1/quote`, timeout 2–3s, **one JSON body for all lines**.
11. **2xx:** parse; reject negative/mismatched SKUs; apply floor vs 1.4 list; upsert cache by External Id; reset failure count; compute 1.4 fulfillment on the same cart; return DTO `source=SDPE`.
12. **429/503:** one retry with short backoff; then fallback.
13. **Timeout / 5xx / parse error:** increment failure count; if ≥ threshold, set circuit open + insert Case `SDPE_Outage` (see assignment); fallback.
14. **Fallback:** for each SKU+RDC, cache row with `Received_At__c` within TTL → `source=CACHE`. Else 1.4 PBE + volume/contract % → `source=LIST`. Fulfillment still from 1.4.
15. LWC shows totals. Optional badge: “Promotional perishable price” vs “Standard price”.

### C. Submit (must succeed even if SDPE is down)

16. Submit Apex runs **the same quote method again** (no client-sent unit prices).
17. Persist 1.4 snapshot including `Price_Source__c` and unit prices awarded.
18. Continue 1.5 allocation / 2.2 GFSR as today. **SDPE failure does not block** those (food-safety is a different gate).

### D. Keep fallback healthy

19. Scheduled Queueable every 5–15 minutes: ping SDPE; if up, close circuit, close outage Case, refresh **top movers** into cache (so a long outage still has recent prices).
20. Optional inbound: SDPE or MuleSoft upserts cache via Connected App (API user = same integration user). Idempotent External Id.

### E. After-hours / spike

21. Circuit **open** during a spike of 5xx: **zero** checkout callouts; Salesforce-only path (cache/list) keeps 50k-order days from queueing on a dead engine.

## 6. Sharing, security, assignment

**Sharing:** Cache, health, and logs are **Private**. HVU **no Read**. They only see the number on **their** Order (existing CBP / Sharing Set). Restriction rules unnecessary if only Integration + Pricing IT see the cache (public group `FSG_Pricing_IT`).

**Security:** Named Credential; no SDPE host in CSP/CORS; `StripInaccessible` / USER_MODE on Account/Order; payload minimization; logs without bodies; TLS; guest cannot call Apex; submit recalc; floor so a compromised SDPE cannot give $0.

**Assignment:** Cache owned by Integration User. Circuit-open Case → Omni queue **IT_Integration** / Pricing ops (region optional). Humans never own the quote.

## 8. Final outcome (brief)

- Checkout **always** returns a goods price: **live SDPE → TTL cache → 1.4 Price Book**, then **1.4 fulfillment**.
- Salesforce sends a **server-side inventory DTO** in **one** Named Credential callout; the portal **never** talks to SDPE.
- A **circuit breaker** stops calling a dead engine; checkout stays on Salesforce data.
- Buyers cannot see cache/logs or spoof prices; the Order records whether the price was **SDPE, cache, or list**.
- SDPE outage opens an **internal Case**; it does **not** stop checkout (unlike 2.2 GFSR at the border).
