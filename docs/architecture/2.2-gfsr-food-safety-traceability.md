# 2.2 Global Food Safety & Traceability Registry (GFSR)

## Salesforce Architecture Design — FreshSource Global (FSG)

**Best-path design** on Sales Cloud + Service Cloud + Experience Cloud. GFSR is **external** (national/supranational).  
**Depends on:** 1.1 farm certs/Files, 1.5 shipments/RDC, 1.2–1.3 Orders, 1.6 Cases.  
**Contrast with 2.1 SDPE:** pricing **fail-open**; **cross-border dispatch fail-closed** until GFSR says the lots are Valid.

**Salesforce patterns:** *Fire and Forget* (Platform Event → Queueable) for register/update; *Request and Reply* at the border gate; *Batch Data Synchronization* nightly; inbound REST upsert by External Id; **Named Credential + mTLS**; no browser callouts.

---

## 1. Designed problem statement

For **international** perishable shipments, Salesforce must **bi-directionally** sync with GFSR:

| Data | Direction |
| --- | --- |
| Batch **lot numbers** | Out: register; In: Valid / Rejected / Hold / Recalled |
| **Farm origin certificates** (1.1) | Out: cert metadata + file hash; In: expiry/revocation |
| **Import compliance docs** | Out: dossier; In: Accepted / Rejected |

Secure: secrets in Named Credentials, least privilege, no guest/HVU access to GFSR. Traceability stays in Salesforce (farm → lot → shipment → order).

---

## 2. Best-path decisions (locked)

| Decision | Choice | Why |
| --- | --- | --- |
| Legal SoR | **GFSR** for official validity | Government/supranational registry |
| Operational SoR | **Salesforce** lots, shipments, Files, Cases | FSG must pick, ship, and support |
| Outbound | Platform Event `GFSR_Outbound__e` → Queueable callout `NC_GFSR` | Guaranteed retry; does not block the farm UI |
| Dispatch gate | **Sync** `GfsrValidationService.validateShipment` | Request–reply at the only moment that must be right |
| Inbound | Apex REST `/gfsr/v1/events` + upsert by `GFSR_Id__c` | Idempotent; works if GFSR cannot wait for Salesforce pages |
| Nightly | Batch GET Pending lots | Catches missed webhooks |
| Auth to GFSR | **OAuth 2.0 Client Credentials + mTLS** on Named Credential (Named Principal) | Same family as 2.1, plus mTLS (typical for food-safety APIs). Not Per-User. |
| Inbound auth | Connected App, **JWT Bearer or Client Credentials**, IP allowlist | Integration User only |
| Fail closed | International shipment cannot go **In Transit** unless all lots `Valid` | Food safety > uptime (opposite of 2.1) |
| Documents | Salesforce Files; outbound **SHA-256 + metadata**; binary only if GFSR requires | No PDFs in long text; no public ContentDistribution |
| Middleware | **Direct REST first**; MuleSoft only if GFSR is EDI/AS2/SOAP | Stay on core unless protocol forces it |
| External Objects | **Not the operational SoR** | Connect is a live query. Bi-directional **sync**, Files, Sharing Sets, fail-closed dispatch, and recall Cases need local `Lot_Batch__c`. Optional `__x` peek for Compliance UI only. |

## 3. Data model

| Object | Role |
| --- | --- |
| `Lot_Batch__c` | Lot number, farm Account, Product, harvest/expiry, origin cert lookup, `GFSR_Id__c` (External Id), `GFSR_Status__c` |
| `Shipment_Lot__c` | Junction shipment ↔ lot + qty; `Buyer_Account__c` for Sharing Set |
| `Import_Compliance_Doc__c` | Phytosanitary/customs/origin; File; `GFSR_Document_Id__c` |
| `Food_Safety_Certification__c` | 1.1 origin cert (reuse, do not clone blobs) |
| `GFSR_Sync_Log__c` | Direction, correlation Id, HTTP, retries; **no** PII body |
| `Cold_Chain_Shipment__c` | `Is_International__c`; `Fulfillment_DC__c`; blocked until Valid |

`GFSR_Status__c`: `Not_Submitted` → `Pending` → `Valid` \| `Rejected` \| `Hold` \| `Recalled`.

---

## 4. Authentication (best flow)

**Salesforce → GFSR (Named Principal, not the chef or farmer):**

1. External Credential **OAuth 2.0 Client Credentials** (token URL + client id/secret on the principal).
2. Named Credential `NC_GFSR`: API base URL + **mutual TLS** certificate (Salesforce Help: Named Credentials / client certificates).
3. Apex: `callout:NC_GFSR/...` only. Token refresh is automatic. **401 after refresh** = fail-closed at dispatch, retry Queueable for async upserts.
4. Permission: **External Credential Principal Access** on the **integration / automation user** that runs Queueable and `validateShipment`. HVU/Partner **do not** call GFSR (unlike 2.1 quote, which runs in the buyer transaction). Dispatch Apex runs as **Order Ops / automation**, not the portal user.

**GFSR → Salesforce:**

5. Connected App; JWT Bearer (preferred for agencies) or Client Credentials.
6. Integration User: CRUD only on lot/doc/log + create Case. **No** View All Data if Apex REST is scoped.
7. IP allowlist; TLS only.

Farmers authenticate to **Experience Cloud** (1.1 Partner). That login is **not** a GFSR login.

**External Objects:** do **not** replace this sync. OData/`__x` cannot host Files, Sharing Sets, or a last-known `GFSR_Status__c` when the registry is down. Dispatch must read **local** Valid/Hold from the last inbound event plus a **sync validate** when GFSR is up.

## 5. Detailed step-by-step

### A. Setup

1. Objects, External Ids, Shield encryption on lot/cert numbers, Private OWD.
2. `NC_GFSR` (OAuth CC + mTLS). Connected App + Integration User.
3. Permission sets: `PSG_GFSR_Integration`; Q&C/Compliance groups; **no** guest Apex.
4. Custom Metadata: country pairs that are `Is_International__c`; required doc types per lane.
5. Omni queues `Trade_Compliance_{Region}` and reuse 1.1 Q&C.

### B. Outbound — register lot and certs (Fire and Forget)

6. Farm or Q&C creates `Lot_Batch__c`, links valid 1.1 origin cert + Files. Status `Ready_To_Submit`.
7. After-save Flow publishes `GFSR_Outbound__e` (LotId, action `UpsertLot`).
8. Queueable reads lot + cert metadata + file hash; POST `callout:NC_GFSR/lots`.
9. 2xx: store `GFSR_Id__c`, status `Pending` or `Valid` if the API is synchronous. Log correlation Id.
10. 5xx/timeout: chain Queueable (backoff). After N failures: Case `GFSR_Sync_Failure` → Trade Compliance Omni. **Do not** set Valid.
11. When warehouse attaches `Import_Compliance_Doc__c`, same event with action `UpsertDossier`.

### C. Cross-border dispatch gate (Request and Reply)

12. 1.5 allocates RDC; warehouse adds `Shipment_Lot__c` (FEFO). If dest country ≠ origin → `Is_International__c`.
13. Before Activate / In Transit, Flow calls `GfsrValidationService.validateShipment(shipmentId)` (**sync**, 5–8s timeout — not 2s like SDPE; this call is allowed to wait).
14. GFSR returns current status for those `GFSR_Id__c`s. All `Valid` + certs not revoked + required docs `Accepted` → allow In Transit.
15. Else **addError** / stay Allocated. Case to Q&C with reason. Buyer portal: “food-safety / import clearance pending.” **No** silent ship if GFSR is down.

### D. Inbound — status, hold, recall

16. GFSR POST `/services/apexrest/gfsr/v1/events` with correlation Id, `GFSR_Id__c`, new status, optional doc statuses.
17. If correlation Id already on `GFSR_Sync_Log__c` → 200 no-op (idempotent).
18. Upsert lot/docs. If `Hold` or `Recalled`: lot ineligible; release **unused** 1.5 reservations; insert parent Q&C Case; fan-out **child Cases** to each `Buyer_Account__c` on in-transit/delivered `Shipment_Lot__c` (1.6 sharing).
19. Nightly Batch: `Pending` older than SLA → GET GFSR → align status.

### E. Experience Cloud

20. **Supplier site:** CRUD **own** lots/certs (1.1 sharing). See `GFSR_Status__c`. Cannot invoke `NC_GFSR`.
21. **Buyer site:** lot number + Valid/Hold/Recalled on **their** shipment only (Sharing Set on `Shipment_Lot__c` via `Buyer_Account__c`). Import Files **hidden**.
22. Guest: nothing.

---

## 6. Sharing, security, assignment

**Sharing:** All GFSR objects **Private**. Farms: Partner access where `Supplier_Account__c` = their Account. Buyers: Sharing Set Read on `Shipment_Lot__c` only; FLS hides farm tax id/cert numbers. Import packs: `Trade_Compliance_{Region}` + 1.1 Q&C; **restriction rules** user region = shipment region. Logs: integration + compliance admin only.

**Security:** Named Credential secrets; mTLS; inbound JWT/IP allowlist; encryption; Field History on `GFSR_Status__c`; no public File links; USER_MODE for any buyer-facing status DTO; Integration User **without sharing** only inside the REST class.

**Assignment:** Sync/dispatch fail → Omni Trade Compliance (region/language). Reject/Hold → Q&C Omni (commodity + region). Recall → Q&C Manager parent + per-buyer Cases. Integration User owns inbound DML (no role).

## 8. Final outcome (brief)

- Salesforce holds **farm → lot → shipment → order**; GFSR is the **legal** validator for lots, origin certs, and import docs.
- **Bi-directional:** outbound Queueable register/update; **sync validate** before international In Transit; inbound REST for Valid/Hold/Recall; nightly GET reconcile.
- **OAuth Client Credentials + mTLS** (Named Principal) out; JWT/Client Credentials + IP allowlist in. Farmers’ portal login is **not** GFSR auth.
- **International dispatch blocks** until lots are `GFSR_Valid`; GFSR downtime does **not** clear the border (opposite of 2.1 checkout).
- Farms see **own** lots/certs; buyers see **lot status on their shipment**; import dossiers stay with regional Compliance/Q&C.
- Recalls freeze lots, free unused capacity, and **assign** Q&C plus customer Cases.
