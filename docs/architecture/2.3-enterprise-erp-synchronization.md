# 2.3 Enterprise ERP Synchronization (SAP S/4HANA)

## Salesforce Architecture Design — FreshSource Global (FSG)

**Best-path design** on **Sales Cloud + Service Cloud + Experience Cloud only**. SAP S/4HANA is **external** (financial ledger). No Commerce Cloud, CPQ, Order Management, Revenue Cloud, or Salesforce Billing.

**Depends on:** 1.2/1.3 Orders + `Invoice__c`; 1.1 Official Supplier Accounts; 1.2 `Volume_Accumulator__c` / `Rebate_Accrual__c`; 1.5 delivered shipments (payout trigger); 1.4 fee SKUs on OrderItems.

**Contrast with 2.1 / 2.2**

| Integration | Timing | Pattern | Failure mode |
| --- | --- | --- | --- |
| 2.1 SDPE | Checkout, seconds | Request and Reply | **Fail-open** (cache / list price) |
| 2.2 GFSR | Before international In Transit | Request and Reply + inbound REST | **Fail-closed** at the border |
| **2.3 SAP** | **End of each regional business day** | **Batch Data Synchronization** | **Fail-closed for posting** (no double-book); commercial ops continue |

**Salesforce patterns used** (Architects Guide — *Integration Patterns and Practices*; *Data Integration with Salesforce* decision guide):

| Pattern | Where used |
| --- | --- |
| *Batch Data Synchronization* (Salesforce = commercial master) | ETL / iPaaS **pulls** frozen close lines via **Bulk API 2.0**, transforms, posts to SAP, **upserts** SAP document numbers back |
| *Remote Call-In* | SAP / middleware writes posting results (Bulk upsert or Apex REST for exceptions) |
| Named Credential `NC_SAP` (optional outbound) | Salesforce-initiated retry of a **failed close run** or master-data probe — not the primary 50k-order extract |

Salesforce is a **spoke**. Middleware (MuleSoft Anypoint **or** SAP Integration Suite / CPI — whichever FSG already runs next to S/4HANA) is the **hub**. That middleware is **not** a Salesforce Cloud SKU; core Sales/Service/Experience stay in license scope.

## 1. Designed problem statement

At the **end of every business day**, Salesforce must send SAP S/4HANA a complete, reconcilable set of:

| Commercial document | Salesforce source | SAP financial target |
| --- | --- | --- |
| **Finalized orders** | Standard `Order` + `OrderItem` (Activated; typically delivered) | SD Sales Order (audit) **and/or** billing source for AR |
| **Fulfilled invoices** | Custom `Invoice__c` + Files (1.3; no Salesforce Billing) | Customer billing document / FI-AR customer invoice |
| **Vendor payouts** to farms | `Vendor_Payout__c` (new; from delivered `Shipment_Lot__c`) | FI-AP supplier invoice + payment run |
| **Corporate rebates** | `Rebate_Accrual__c` (1.2 period calculation) | Customer credit memo / condition-contract settlement |

**Purpose:** financial **ledger reconciliation** (AR, AP, rebate liability). Not live checkout (2.1) and not food-safety clearance (2.2).

**Secure:** Integration User + Bulk API / Connected App only. Experience Cloud **guest, HVU, and Partner never call SAP**. Buyers still see invoices; farms still see payout status — locally.

FSG operates **14 time zones**. “End of business day” is **per region**, not one UTC midnight (Architect Guide: segment global batch windows so a load does not collide with users still trading).

## 2. Best-path decisions (locked)

| Decision | Choice | Why (Salesforce recommendation) |
| --- | --- | --- |
| Commercial SoR | **Salesforce** Order, Invoice, payout, rebate until `ERP_Status__c = Posted` | Orders are captured on Sales Cloud; SAP does not own the chef portal |
| Financial SoR | **SAP S/4HANA** GL, AR, AP, vendor payment, fiscal period | Ledger lives in ERP. Do **not** replicate the SAP GL into Salesforce |
| Primary extract | **Middleware pulls Bulk API 2.0** query of `ERP_Close_Line__c` | *Batch Data Synchronization*: “Good/Best when Salesforce is data master — ETL + Bulk API 2.0.” Apex callout-per-invoice is **suboptimal** at 50k orders/day (100 callouts/tx, CSRF, no distributed tx) |
| Hub | **MuleSoft or SAP CPI** (existing FSG/SAP landscape) | Decision guide: use ESB/ETL if in the landscape; mandatory properties are **ETL, transformation, queuing, orchestration**. Salesforce cannot join a distributed SAP posting transaction |
| Close grain | **`ERP_Close_Run__c` per Region + Business Date** | 14 time zones; Guide: “data segmentation… record types and filtering” for always-on orgs |
| Freeze | Snapshot lines **before** extract; source records locked to `Extracted` | Idempotent reruns; finance can prove what was sent |
| Idempotency | Salesforce Id / document number as SAP **External Reference** | Retry posts the **same** key; SAP rejects or returns the existing document — no double GL |
| Write-back | Bulk API 2.0 **upsert** `SAP_Document_Number__c` by External Id | Same pattern inbound; Integration User API Only |
| Control totals | Count + amount per document type on the run vs SAP ACK | Ledger reconciliation is a **batch window** property (Guide: timeliness = finish inside the window, not seconds) |
| Auth to Salesforce | Connected App **JWT Bearer** (or Client Credentials); Integration User | Decision guide: API-only integration user; External Client App / Connected App — not SOAP login |
| Auth to SAP (if SF posts exceptions) | Named Credential **OAuth 2.0 Client Credentials + mTLS**, Named Principal `NC_SAP` | Same family as 2.1 `NC_SDPE` / 2.2 `NC_GFSR`. Not Per-User |
| Master data | Account.`SAP_BP__c`, Product2.`SAP_Material__c` **before** commercial post | SAP will reject documents without Business Partner / Material. Thin daily **delta** of new Accounts/Products, not a full BP replicate |
| External Objects | **Not** the close SoR | Connect **queries** SAP; this problem is **scheduled bi-directional sync** plus freeze, control totals, and Files. Optional `__x` peek of SAP open items for Finance UI only |
| CDC / Platform Event per Order | **Rejected as primary** | Near real-time; no regional close, no control totals, high-volume CDC is an add-on, and posting would still need a hub |
| Salesforce Billing / Revenue Cloud | **Out of scope** | Stay on core; keep custom `Invoice__c` |
| Experience Cloud | No SAP callouts; FLS hides ERP logs | Portal login ≠ SAP login (same split as 2.1/2.2) |

**Rejected:** Batch Apex POST of each invoice to SAP as the primary path; Data Loader as the strategy; Outbound Messaging; browser callouts; fail-open GL posting; one global midnight job.

**Fallback if FSG has no iPaaS yet (phase 0 only):** Scheduled Batch Apex `Database.AllowsCallouts` posts **already-frozen** `ERP_Close_Line__c` rows to SAP OData `$batch` via `NC_SAP`, chunk size small enough for 100-callout and heap limits. Promote to Bulk-extract hub before international volume. Do **not** start production 50k-order days on this path.

## 3. Data model

### 3.1 Salesforce objects

| Object | Role |
| --- | --- |
| `Order` + `OrderItem` | Finalized commercial order (1.2/1.3). `ERP_Status__c`, `SAP_Sales_Order__c`, `ERP_Close_Run__c` |
| `Invoice__c` | Fulfilled AR invoice + PDF File (1.3). `Invoice_Number__c` External Id, `SAP_Billing_Doc__c`, `ERP_Status__c` |
| `Vendor_Payout__c` | Amount owed to `Official_Supplier` Account; lines optional `Vendor_Payout_Line__c` (lot/shipment). `Payout_Number__c` External Id, `SAP_Supplier_Invoice__c`, `SAP_Payment_Doc__c` |
| `Rebate_Accrual__c` | HQ/period rebate from 1.2 accumulator. `Rebate_Number__c` External Id, `SAP_Credit_Memo__c` |
| `ERP_Close_Run__c` | **Control table:** Region, `Business_Date__c`, Status, started/finished, **control counts and amounts** by type, watermark, error text |
| `ERP_Close_Line__c` | **Immutable snapshot** of one document in that run (type, source Id, External Id, amount, currency, payload hash). `SAP_Document_Number__c` written back |
| `ERP_Sync_Log__c` | Direction, job Id, HTTP/Bulk job, retries; **no** invoice-line PII in the body |
| `Country_Lane__mdt` / `ERP_Close_Window__mdt` | Region → time zone → local close hour; company code; sales org; SAP plant |
| Account | `SAP_BP__c` (External Id), `SAP_Company_Code__c`, buyer vs supplier record type |
| Product2 | `SAP_Material__c` (External Id) |

`ERP_Status__c` on source documents: `Not_Ready` → `Ready` → `Extracted` → `Posted` \| `Error`.  
`ERP_Close_Run__c.Status__c`: `Draft` → `Frozen` → `Extracted` → `Posted` \| `Partial` \| `Failed`.

**Eligibility (Ready):**

- **Order:** Status Activated; not cancelled; `Is_International__c` shipments already GFSR-cleared if 2.2 applies; typically `Invoice__c` exists (FSG policy: invoice on Delivered).
- **Invoice:** Status Open or Paid; Amount ≠ 0; PDF optional for SAP (hash if sent).
- **Vendor payout:** Status Approved (Finance); supplier `SAP_BP__c` populated; tied to delivered lots.
- **Rebate:** Status Calculated (nightly 1.2 batch already ran for that period/region).

### 3.2 SAP mapping (illustrative S/4 APIs)

Middleware maps snapshot lines — Apex does **not** hard-code IDoc segments.

| Close line type | SAP object (typical) | API class |
| --- | --- | --- |
| Finalized order | Sales Order | OData V4 `API_SALESORDER` / V2 `API_SALES_ORDER_SRV` (deep insert) **or** omit if FSG posts **billing-only** and keeps Order in Salesforce |
| Fulfilled invoice | Billing document / FI customer invoice | OData billing / Journal Entry post |
| Vendor payout | Supplier invoice (FI-AP) then payment | Supplier Invoice OData; payment run stays in SAP |
| Corporate rebate | Customer credit memo | Billing credit memo or Condition Contract settlement |
| New buyer / farm | Business Partner | `API_BUSINESS_PARTNER` (delta only) |
| New SKU | Product master | Product / Material API (delta only) |

**Ledger hit:** AR and AP documents post to FI. Sales Order alone does **not** reconcile the GL — invoices and payouts do. Include finalized orders in the close file for **audit completeness**; Finance configures whether they post SD or are statistical.

```text
Account (HQ/Branch/Micro/Supplier)  SAP_BP__c
Order ── Invoice__c ── ERP_Close_Line__c (AR)
Official_Supplier ── Vendor_Payout__c ── ERP_Close_Line__c (AP)
Contract ── Rebate_Accrual__c ── ERP_Close_Line__c (credit)
ERP_Close_Run__c 1──* ERP_Close_Line__c
```

## 4. Authentication (best flow)

Three hops. Do **not** mix them (same rule as 2.1/2.2).

| Hop | Who | Best flow | Why |
| --- | --- | --- | --- |
| 1. Farmer / buyer → Salesforce | Partner / HVU | Experience Cloud Login Discovery + MFA | Sharing from User → Contact → Account |
| 2. Middleware → Salesforce | Integration User | Connected App **JWT Bearer** (preferred) or Client Credentials; **Bulk API 2.0** | Decision guide: API-only user; JWT is the agency/ERP pattern (certificate, no password) |
| 3. Middleware → SAP | iPaaS technical user | SAP Communication Arrangement OAuth / certificate (CPI) or MuleSoft SAP connector | SAP CSRF and session stay in the hub — **not** in Apex |

```mermaid
sequenceDiagram
    participant Sched as Regional close scheduler
    participant SF as Salesforce
    participant Hub as MuleSoft or SAP CPI
    participant SAP as S/4HANA
    Sched->>SF: Flow: freeze Ready docs for Region+Date
    SF->>SF: Insert ERP_Close_Run + Lines; status Extracted
    Hub->>SF: Bulk API 2.0 query Close_Line where Run = today Frozen
    SF-->>Hub: CSV/JSON snapshot
    Hub->>Hub: Transform + control totals
    Hub->>SAP: OData $batch / IDoc (idempotent External Reference)
    SAP-->>Hub: Document numbers
    Hub->>SF: Bulk upsert SAP_Document_Number, status Posted
    alt mismatch or SAP down
        Hub->>SF: Partial/Failed + Finance Case
    end
```

### 4.1 Middleware → Salesforce (Help: Connected Apps / OAuth JWT Bearer / Bulk API 2.0)

1. Connected App `FSG_SAP_ERP`: scopes `api`; JWT: upload hub public cert; **Admin approved users are pre-authorized**; pre-authorize Integration User profile. Client Credentials if the hub cannot mint JWTs.
2. Integration User: **API Only**; CRUD `ERP_Close_Run__c` / `ERP_Close_Line__c` / log; **Edit** ERP fields on Order/Invoice/Payout/Rebate; **Create** Case. **No** View All Data if sharing is set via a Finance role/group the user is in — typically this user is **without sharing** in Apex exception paths only. **No role** (skew).
3. IP allowlist to hub egress. TLS 1.2+. Optional inbound mTLS (port 8443) on the Integration User.
4. Use **Bulk API 2.0** ingest/query (Architect Guide: Best for bulk). REST Composite only for < a few hundred exception rows.

### 4.2 Salesforce → SAP (exception / probe only)

5. External Credential `EC_SAP`: OAuth 2.0 Client Credentials, Named Principal `FSG_SAP_App`.
6. Named Credential `NC_SAP`: S/4 or CPI facade URL; attach **mTLS** client certificate; Generate Authorization Header; no merge fields in body.
7. Permission set `PSG_SAP_Callout`: External Credential Principal Access — **automation user only**. Not HVU/Partner (unlike 2.1 quote).
8. Apex `callout:NC_SAP/...` only if the hub is down and Finance triggers **Replay Close Run** for a small Partial set. Token refresh is automatic.

Farmers and chefs authenticate to **Experience Cloud**. That login is **not** an SAP login.

## 5. Detailed step-by-step

### A. Setup (once)

1. Custom objects and External Ids above; OWD **Private** on ERP objects, Invoice, Payout, Rebate. Order remains **Controlled by Parent** (1.2/1.3).
2. Field History on `ERP_Status__c` and SAP document number fields.
3. Connected App + Integration User; optional `NC_SAP`.
4. Permission sets:
   - `PSG_ERP_Integration` — Integration User.
   - `PSG_ERP_Finance` — regional Finance (Read/Write runs; Read lines; restriction rule Region).
   - Buyers: existing Invoice Sharing Set Read; **no** ERP objects.
   - Farms: Read **own** `Vendor_Payout__c` (`Supplier_Account__c` = their Account); **no** close runs.
   - Guest: nothing.
5. CMDT `ERP_Close_Window__mdt`: Region, time zone, local close hour, SAP company code, sales org, currency.
6. Omni queue `Finance_ERP_{Region}` (language skill).
7. Master data: Flow/Batch stamps `SAP_BP__c` / `SAP_Material__c` when Finance or the hub allocates them (inbound upsert). **Block Ready** if those Ids are blank.

### B. Make documents Ready (intraday, Salesforce-only)

8. Order Ops **Activates** Order (HVU cannot Activate — 1.2). 1.5 delivery → Flow creates/updates `Invoice__c` (1.3). Set Invoice `ERP_Status__c = Ready` when Amount is final.
9. Delivered `Shipment_Lot__c` → nightly or on-delivery Batch builds/updates **Approved** `Vendor_Payout__c` (farm unit cost × qty − quality deductions from 1.6). Finance may require a two-step Approve. Then `Ready`.
10. 1.2 nightly volume batch updates `Volume_Accumulator__c`. On period close (or daily accrual policy) insert `Rebate_Accrual__c` `Calculated` → `Ready`.
11. **Do not** call SAP in these Flows.

### C. Regional close freeze (end of that region’s business day)

12. Scheduled Flow (timezone from CMDT) for each Region: create `ERP_Close_Run__c` (`Draft`) for `Business_Date__c` = that region’s today.
13. Queueable/Batch selects Ready documents for that Region (Order/Invoice/Payout/Rebate `Region__c` or Account.Region). **FOR UPDATE** the source rows; set `Extracted`; insert `ERP_Close_Line__c` with amount, currency, source External Id, SHA-256 of canonical JSON.
14. Roll **control totals** onto the run (count/amount by type). Status `Frozen`. Source records cannot be edited commercially without Finance (validation: Extracted/Posted is locked).
15. If a second freeze is attempted the same Region+Date, **no-op** (unique External Id `Region_Date__c` on the run).

### D. Extract and post (middleware hub — Salesforce-recommended)

16. Hub job (same regional window + buffer): JWT to Salesforce; **Bulk API 2.0 query**  
    `SELECT ... FROM ERP_Close_Line__c WHERE ERP_Close_Run__r.Status__c = 'Frozen' AND Region__c = :region`.
17. Hub transforms to SAP OData `$batch` or IDoc (`INVOIC`, `ACC_DOCUMENT`, supplier invoice). Sets **External Reference** = Salesforce External Id.
18. Post to S/4HANA. **Idempotent:** SAP returns existing document if the reference already posted.
19. Compare SAP posted count/amount to run control totals (tolerance CMDT, usually **zero**).
20. **Bulk upsert** lines and parents: `SAP_Document_Number__c`, `Posted`. Run `Posted` if all match; `Partial` if some SAP errors; `Failed` if hub/SAP unavailable.
21. Partial: those lines `Error` + reason; source `ERP_Status__c = Error`; **do not** unlock successfully Posted lines.
22. Case `ERP_Close_Failure` → Omni `Finance_ERP_{Region}` with run Id and mismatch report.

### E. Inbound payment / credit status (SAP is financial SoR)

23. After SAP payment run / clearing, hub upserts `Invoice__c.Status__c = Paid`, `Vendor_Payout__c` Paid, `SAP_Payment_Doc__c`. **Do not** let chefs mark invoices Paid in the portal.
24. Fiscal-period lock in SAP: hub refuses new posts; Salesforce close run stays Frozen/Failed; Finance waits for period open or posts to next period per FSG policy (CMDT).

### F. Replay and audit

25. Finance button **Replay errors** on a Partial run: sets Error lines back to Frozen (same run, same External Ids) and notifies the hub. Safe because SAP is idempotent on External Reference.
26. Nightly Batch: Frozen runs older than SLA with no write-back → Case (missed hub job).
27. Retain close lines for the audit period; archive Orders per 1.2 LDV **after** `Posted` and retention (Big Object / warehouse). Never archive `Extracted` but not `Posted`.

### G. Experience Cloud

28. **Buyer site:** Invoice list + PDF + Paid/Open (1.3 Sharing Set). Optional display of SAP billing number. No close runs, no payouts, no SAP callouts.
29. **Supplier site:** own `Vendor_Payout__c` status (Approved / Paid) and amount. No other farms; no AR invoices.
30. **Guest:** nothing.

## 6. Sharing, security, assignment

**Sharing**

- `ERP_Close_Run__c`, `ERP_Close_Line__c`, `ERP_Sync_Log__c`: Private; Finance groups + Integration User. **Restriction Rules:** user Region = run Region.
- `Invoice__c`: existing buyer Sharing Set Read.
- `Vendor_Payout__c`: Partner sharing where `Supplier_Account__c` = farm Account (one role per farm, 1.1). FLS hides cost build-up if needed.
- `Rebate_Accrual__c`: HQ Finance + SAM internally; **no** HVU (chefs must not see rebate internals — 1.2 FLS). Optional HQ merchandiser Read.
- Order CBP unchanged.

**Security**

- JWT/Connected App inbound; secrets never in Apex; `NC_SAP` only for exception replay.
- Payload minimization to SAP (no chef emails, no card data, no GFSR cert blobs).
- Logs without full invoice lines (store hash + External Id).
- `USER_MODE` on any portal DTO.
- Guest lockdown.
- Optimistic locking: once Extracted, UI edits `addError`.
- Salesforce is **not** in the SAP LUW; compensation = reverse document in SAP + Error line, never “delete and resend as new Id”.

**Assignment**

- Close failures → Omni Finance ERP (region/language).
- Master-data missing BP/Material → Case to Master Data / SAM, not the hub retry loop.
- Integration User owns freeze DML and inbound upserts (no role).
- Humans never own the Bulk job.

**Scale (50k orders/day, LDV)**

- Close is **regional** (thousands of lines per run, not 50k in one transaction).
- Bulk API 2.0 for extract and write-back (Guide: Best for bulk). Group child lines by parent Account in the hub when upserting to reduce **row lock** contention (Guide: group imported data by parent key).
- No roll-up summaries of posted amount to HQ Account.
- Skinny close-line object (no long text payload; hash + typed columns).
- Do not fire heavy Order triggers on the Bulk write-back: `ERP_Status__c` updates should be **selective** (recursion guard).

| Need | Salesforce guidance |
| --- | --- |
| EOD financial extract at 50k-order volume | *Batch Data Synchronization* — ETL/iPaaS + **Bulk API 2.0**; Salesforce is spoke, hub stores watermarks/control tables |

| Not Connect as SoR | External Objects query remote data; this problem is **scheduled synchronization** + freeze + control totals |
| Not CDC as primary | CDC is near real-time change notification; financial close needs a **designated batch window** and totals |
| Portal | Private OWD; Sharing Sets on buyer Invoice / farm Payout only; no guest |

## 8. Final outcome (brief)

- Salesforce remains the **commercial** system of record for orders, invoices, farm payouts, and rebate accruals; **SAP S/4HANA** remains the **financial ledger**.
- Each **region** freezes a dated `ERP_Close_Run__c` at **local** end of day; middleware **pulls Bulk API 2.0**, posts to SAP with Salesforce External Ids, and **upserts** SAP document numbers.
- Posting is **idempotent and fail-closed**: retry the same key; never silent-double-book; ops can still take orders (unlike 2.2 dispatch, unlike 2.1’s need for an immediate price).
- **OAuth JWT / Client Credentials** into Salesforce; SAP credentials stay in MuleSoft or SAP CPI; optional `NC_SAP` + mTLS only for exception replay. Portal users never call SAP.
- Buyers see **invoice Paid/Open**; farms see **own payout** status; rebate and close files stay with Finance.
- Control totals on the run vs SAP ACK drive Omni Finance Cases; missing Business Partner/Material blocks Ready, not a poison-pill retry.
- Stay on **Sales + Service + Experience Cloud**; the hub is existing ERP middleware, not a new Salesforce Cloud.
